# Operations Maturity System

An interactive operating intelligence platform for understanding, diagnosing, designing, and improving mature business operations.

## Core Philosophy

**Every business has an operating system. Most just haven't designed it intentionally.**

**Stop fixing symptoms. Start designing systems.**

The Operations Maturity System (OMS) is designed to help users understand how organizations actually work, identify operational constraints, build stronger operating systems, and continuously improve them.

## Core Experience

The platform is organized around four primary actions:

- **Learn** — Understand how mature operations work.
- **Diagnose** — Identify what is actually broken.
- **Build** — Design the systems required to improve.
- **Improve** — Continuously strengthen the operating system.

## Operations Maturity Framework

OMS views mature operations through six connected layers:

1. **Direction** — Where are we going?
2. **Design** — How should the organization work?
3. **Execution** — How does work actually happen?
4. **Management** — How do we run the system every day?
5. **Intelligence** — How do we know what is happening?
6. **Evolution** — How does the organization become better?

## Repository Structure

- `/css` — global, component, and responsive styling
- `/js` — application behavior and feature logic
- `/data` — structured operational knowledge and application content
- `/pages` — major product experiences
- `/assets` — images and visual assets

## Development Principles

The repository is intentionally modular.

When developing the application:

- Preserve the existing repository structure.
- Do not collapse the application into a single file.
- Keep operational content in `/data`.
- Keep application logic in `/js`.
- Keep styling in `/css`.
- Keep major experiences in `/pages`.
- Reuse shared patterns rather than duplicating functionality.
- Build incrementally.
- Maintain compatibility with GitHub Pages.
